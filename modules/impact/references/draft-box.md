# 微信公众号草稿箱操作

运行 `import_word_draft.py` 的 `--save-draft` 模式须获得用户明确授权，并先复核转换预览、标题、简介和图片。[Word 导入命令和断点处理](word-import.md)

## 环境

- 使用 Google Chrome，在微信公众号官方页面登录，并保留当前操作对应的一个后台首页标签。登录过期时，请用户在官方页面扫码。
- 安装 Kimi WebBridge 的 Chrome 扩展和本地服务。脚本直连回环地址 `http://127.0.0.1:10086/command`，使用 `wechat-impact-article` 会话。
- 仓库脚本目录需要可写，以便平台操作期间持有本地锁。每次导入使用独立的本地输出目录，重跑同一次导入时沿用该目录和状态文件。

## 编辑器入口与控件

1. 在官方后台首页「新的创作」中点击「文章」。脚本匹配 `.new-creation__menu-item` 中可见、标题为「文章」的唯一菜单项，再通过 WebBridge 点击。新建文章页使用 `type=77` 和 `createType=0`。
2. 确认新标签是空白文章编辑器并标记本次导入。若已打开其他未保存的文章，先保留其内容并退出该编辑页。断点恢复要求页内标记和标题均与本次导入匹配。
3. 标题写入 `textarea#title` 或 `textarea.js_title`，并同步可见的 `.title-editor__input .ProseMirror`。可选作者使用 `input#author` 或 `input.js_author`，简介使用 `textarea#js_description` 或 `textarea[name=digest]`。
4. 正文写入 `.view.rich_media_content .ProseMirror` 或 `.mock-iframe-body .ProseMirror`。在本地预览确认结构后，再核对后台正文内容和图片。
5. 提供封面时，从 `#js_cover_area` 打开「选择图片」。在对话框上传封面后，选择对应图块，依次点击「下一步」和「确认」。检查封面预览是否出现。
6. 回读标题和简介，确认归属后，只点击 `#js_submit` 中精确显示为「保存为草稿」的可用控件。入口或控件无法确认时停止并报告。

## 回读与恢复

- 保存后，状态文件记录本次标题、草稿编号 `appmsgid` 和核验进度。凭据和带凭据的后台 URL 不写入命令参数、状态或日志。
- 回读保存后的编辑页，核对标题与图片，再从后台首页进入「草稿箱」，匹配可见卡片上的同一编号和标题。列表选择器尚待实测，无法确认时保留 `saved`，重跑只回读。重跑前可在官方后台重新打开首页及对应草稿的编辑页。
- 编辑页和草稿箱列表均确认后标为 `verified`。缺封面或正文图，以及图片无法确认时，报告配图不完整。
- 点击保存后若未取得编号，先在官方后台人工核对。保留原输出目录及状态，脚本会阻止自动重试保存。
